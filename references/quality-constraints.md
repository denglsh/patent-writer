# 专利实体质量约束（保护范围与撰写红线）

本文件是格式 playbook 之外的**实体质量层**：playbook 决定"怎么写"（结构/措辞/复用），
本文件决定"写多宽、写多细、哪些红线不能碰"。阶段 B 第1步（权利要求书）动笔前通读，
第8步终检对照第七节执行。要点综合自知乎专利实务经验帖（来源见文末）。

## 一、保护范围把控（独立权利要求）

1. **独权最小完整性**：只写必要技术特征。判断口诀——"少了它，方案就不成立"。对每个候选特征过四问，任一问答"是"即可下沉从权：
   ① 去掉后还能解决说明书写明的技术问题吗？
   ② 去掉后还能与最接近的现有技术区分开吗？
   ③ 去掉后独权仍是完整闭合的技术方案吗？
   ④ 说明书原文语气是"必须/不可缺少"，还是"例如/优选"？
2. **两个极端都不许碰**：
   - 过宽：缺必要技术特征（细则 R20.2）、把现有技术圈进保护范围（A22.3）、上位概括得不到支持（A26.4）
   - 过窄：把优化特征/具体结构/具体材料写进独权。概括写法示例：转轴/齿轮/皮带 → "驱动总成"；"通过螺栓固定连接" → "以可拆卸的方式连接"；非关键材料一律不提。
3. **上位概括必须有支撑**：权利要求覆盖范围较宽时，说明书至少给两个不同实施例；功能性限定被视为覆盖所有能实现该功能的方式——若本领域技术人员有理由怀疑某些方式不能解决技术问题，不得使用该概括。
4. **字数参考**：独立权利要求尽量 ≤600 字符（智能审查系统对超长独权标记疑似低质量申请）；中国专利奖获奖首权 145~332 字可作标杆。playbook 给出的字数区间若与本条冲突，以本条为准收紧。

## 二、从属权利要求梯队（退守纵深）

5. **金字塔三层布局**：独权（最宽）→ 次宽层（核心模块的常见实现结构，对手最可能抄）→ 中间层（对手加小特征规避的常见细化）→ 最窄层（辅助结构、具体参数、实施例级）。核心模块配 2~3 条从权，辅助模块 1~2 条。
6. **每条从权必须能回答**："独权被缩时，这条顶上来守住的是什么方案？"答不上来的是凑数，删。
7. **创造性核心改进必须单独成条**——答复审查意见时才有牌可打。最忌创新点全写在独权里、从权全是边角料。
8. **数值布局**：独权圈区间、从权落点值；每个端值在说明书有对应实施例与效果描述；实测只有几个点就写几个点，不为好看外扩成连续区间。
9. **堵规避口自检（扮演对手十分钟）**：拿着独权问——对手改动哪一处最省事就能绕开？该点必须已有从权提前堵住。
10. 从权不得全是独权特征的机械拆分（否则独权一挂全挂）；并列替代方案分组各成一条，不混写。

## 三、清楚性红线（A26.4 清楚）

11. **禁用词**：约、接近、左右、最好、尤其是、必要时、例如、等、厚、薄、强、弱、高温、低温——除非该词在特定技术领域有公认确切含义（如电学"高频/低频"）。
12. **主题名称**必须表明产品或方法类型；禁用"一种……技术""一种……改进/设计/逻辑"等含糊主题。
13. **位置关系**：绝对模糊表述（"a靠近b设置"）有被质疑风险；相对位置表述（"a相较于b更靠近c"）通常可行。
14. **引用规则**：从权择一引用；多项从权不得作为另一项多项从权的引用基础（多项引多项禁止）。
15. 权利要求中不用"如说明书……部分所述""如图……所示"（绝对必要除外）；尽量避免括号（附图标记、数学式、化学式除外）；通常不使用表格。

## 四、说明书支撑（A26.3 / A26.4）

16. **三档写法**：
    - 必须写死：区别于现有技术的特征、从权附加特征、方案成立所需的配合关系与步骤顺序、参数取值依据、需实验证实的效果、数值范围的端值
    - 可上位概括：多个并列实施方式的共同点——须配至少两个实施例
    - 可一句带过：与现有技术共有的特征、本领域公知常规手段
17. **必要内容禁止引证代替**：对满足 A26.3 而言必不可少的内容必须写入说明书本身，不能写"详见某标准/参见某文献"（引证只允许用于背景技术等非必要内容）。
18. **关键参数精准量化**（温度、时间、压力、浓度、转速等），禁用"常温""适量"等模糊表述。
19. **修改预期**：A33 修改不得超出原记载范围——说明书每多写一个端值/实施例，答复阶段就多一条退路；撰写时少写一个，答复时就少一条。

## 五、技术问题与背景技术

20. 技术问题**禁写**"现有技术依赖人工/效率较低"这类空泛表述——审查员会抓"你的方案同样要人工"或"手段含糊无法实施"（A26.3）。技术问题必须具体，且必须是权利要求方案确实能解决的。
21. 背景技术的不足与本方案发明点一一对应（playbook 已有此纪律），且不得把本方案内容泄露进背景技术。

## 六、低质量申请红线

22. **"三位一体"复制粘贴**（权利要求 = 发明内容 = 具体实施方式高度雷同）是低质量申请的标志性写法，可能被认定非正常申请。本 skill 镜像纪律的合规前提：发明内容 = 镜像 + 框架衔接词；具体实施方式 = 步骤段 + 3~4 倍"需要说明的是"扩写 + 带全套数值的实例段——扩写与实例必须有实质增量，禁止无扩写的裸复制。
23. **无贡献特征不凑数**：对技术问题的解决没有贡献的特征，写入权利要求通常也不对创造性产生影响（审查指南第二部分第四章 6.4 新规）——不许用追加无关特征的方式硬凑创造性。
24. **不编造**：对比文件、现有技术、实验数据一律不得虚构；具体实例数值一律走【待填】确认机制。

## 七、终检加做项（并入第8步全文终检）

- [ ] 独权逐特征过四问，确认无优化特征混入
- [ ] 每条从权写出"顶上来守什么"的一句话
- [ ] 扮演对手：找出最省事的规避点，确认已有从权堵口
- [ ] 全文检索第三节禁用词清单
- [ ] 数值端值均有实施例与效果支撑
- [ ] 公式已全部以公式对象写入并对照《公式审计表》核对：无遗漏、无文字化替代；变量全部有解释（含下标上标与单位）；公式间变量衔接闭合
- [ ] 算法类方案：全文无"本发明是一种算法"类客体红线表述；名称与正文体现技术手段而非模型名字；输入/中间步骤/输出三明确；技术效果与传统方法问题一一对应
- [ ] 发明内容/具体实施方式相对权利要求有实质扩写增量（非裸复制）

## 八、写作顺序依据（2026-10-25 补充检索）

社区存在两派：**权利要求先行**（专业代理与 AI 辅助管线的主流）与**说明书先行**（部分个人撰写者）。本 skill 的 playbook 采用权利要求先行，依据：

1. 说明书先写容易"两头打架"：说明书铺得一大片但发明点没圈住，或权利要求想宽、说明书撑不住。先定权利要求，再让说明书"一处不落地接住"，可防说明书与权利要求脱节——脱节正是非正常申请的典型特征。
2. 典型专业管线（TUN 七工序）：交底书结构化（特征穷举、方案级/功能级/实施级分类、创新点溯源）→ 划界检索与竞争定位 → 独权骨架 → 上位概括与范围最大化 → 权利要求生成与校验 → 说明书生成与校验。对应本 skill：第0步方案拆解 + 第1步权利要求书（先行）→ 说明书各章（随后）→ 第8步终检。
3. 摘要时机：常见做法是写完权利要求后概括权1并补技术效果（对应 playbook 第2步）；也有全文完成后写摘要的做法，两者均可，不作为缺陷。
4. 发明内容 = 权利要求镜像（换衔接词）的写法与已授权专利实务描述一致，playbook 第5步同款，配合第六节第 22 条的扩写增量要求执行。

## 九、算法类发明的撰写要点（AI 算法 + 工程场景类）

适用于"AI 算法 + 具体工程场景"（如风电叶片损伤诊断）类发明：算法流程恰恰是核心，但专利里的算法写法与论文完全不同——最大风险是被认定"仅属于数学方法"（A25 客体问题）。要点源自用户提供的算法专利要点（2026-10-25 整理）。

25. **保护的是技术方案，不是模型名字**：禁止只写"采用 Transformer/XX 模型进行识别"这类空泛表述；必须写清数据怎么处理、怎么切片、怎么提特征、怎么融合、怎么输出结果。发明名称同样要体现技术手段（如"一种基于声纹时间序列 Patch 划分与多尺度 Transformer 融合的……识别方法"），不能只挂模型名。
26. **详略程度**：算法写到"本领域技术人员能够复现"的程度——工程流程完整；**不需要**公开全部训练细节（超参搜索过程、训练曲线等可不写）。
27. **技术效果必须对着改进点写**：每条效果 = 传统方法的具体问题（如对微弱裂纹不敏感、工况鲁棒性差、时序信息丢失）+ 本方案的对应改进（如 Patch 时序建模、双流融合、微弱异常增强、长时依赖学习）；与背景技术不足、发明点保持三角对应。
28. **不要把专利写成论文**：不以精度/实验/对比的学术叙事为主线，以**步骤**为主线组织（S1 采集数据 → S2 去噪归一化 → S3 Patch 划分 → S4 构建分支 → S5 融合输出）；对比实验只作为具体实例段里支撑效果的素材。
29. **客体红线表述**：全文禁止"本发明是一种算法 / 一种数学方法"类说法；技术领域按"本发明/本申请属于 XX 技术领域，具体涉及一种基于……的 XX 方法"句式写，把方案锚定在工程技术场景上——这样它就是工程技术方案而不是纯数学方法。
30. **弱化模型名字，强化机制**：授权靠"工程流程完整"而非"模型多先进"。三明确：输入明确（什么传感器采集的什么数据，如"声纹传感器采集的 WAV 音频"）、中间步骤明确（每步做什么变换：Patch 划分、时频变换、特征融合）、输出明确（输出什么结果，如"裂纹类型与损伤等级"）。
