# 公式审计模块（生成与审查规则）

本模块是 SKILL.md 第 8 条公式纪律的执行细则。
触发：技术框架含公式 → 对框架公式审计；技术框架无公式（或某环节明显缺公式）→ 先按逻辑关系生成，再审计。

## 一、公式生成（技术框架没有公式时）

1. 先画逻辑链：沿第0步的 S1~S6 步骤，梳理每步"输入 → 处理 → 输出"的数据流。
2. 只对存在**可量化关系**的环节构造公式，典型位置：
   - 多源特征拼接 / 融合（如 X_i = [AE_i ‖ Sound_i ‖ Acc_i]）
   - 模型 / 状态更新机制（如图节点特征的迭代传播式）
   - 归一化 / 工况修正（如减均值除方差）
   - 优化目标函数与约束条件
   - 误差 / 评估指标定义
   - 权重 / 映射关系（如加权最小二乘）
3. **铁律：公式只能表达技术框架已有的处理逻辑，不得发明框架中没有的环节或方法。** 每条生成公式必须能指出其在框架中的逻辑依据（哪一步的哪句话）。
4. 生成后与框架原有公式合并为统一清单，逐条标注来源：`[框架]` 或 `[生成+依据]`。

## 二、三项审计（对每条公式过一遍）

### 1. 覆盖性——何处需要补充公式

- 逐步骤检查数据流：凡是"文字里写了计算 / 融合 / 更新 / 评估关系，却只用文字描述"的环节，列为建议补公式位置。
- 输出《补充位置清单》：步骤号 + 环节描述 + 建议公式形式。

### 2. 逻辑连贯性——公式之间是否合理、连贯

- **变量衔接闭合**：前一公式的输出变量必须原样出现在后一公式的输入中（同名同符号），链条不断、不跳。
- **与文字一致**：公式表达的关系与权利要求 / 说明书文字描述一致，无矛盾。
- 无循环定义、无单位 / 量纲错配、无与方案无关的孤立公式（有则删除）。

### 3. 变量清晰性——不允许存在模糊变量

- 每个符号有唯一、明确的物理 / 数学含义；禁止未解释的泛化符号（X、A、f 这类必须定义）。
- 每条公式后的"其中 / 式中"段**逐一解释变量**：含义 + 单位 / 量纲（如适用）+ 下标上标含义（如 i 为节点索引、l 为传播轮次）。
- 同一变量全文同名同符号（与术语纪律同源），发现冲突即修。

## 三、审计输出：《公式审计表》

| 编号 | 位置（章节/步骤） | LaTeX | 来源（框架/生成+依据） | 输入→输出变量 | 变量解释完整 | 结论 |
|---|---|---|---|---|---|---|

- 表格连同《补充位置清单》一并展示，请用户编号确认（1=确认 2=修改 3=继续补充）。
- 确认后的审计表是撰写与终检的核对基准。

## 四、执行时点

- **第0步**：生成（如需）→ 三项审计 → 用户确认《公式审计表》。
- **撰写**：按表逐条以公式对象写入（latex2omml.py 转换，独立成段居中，变量定义句紧随）。
- **阶段 C 终检**：对照审计表核对——公式齐全、变量解释齐全、逻辑链仍闭合（章节扩写可能引入新变量，需回查补充解释）。
