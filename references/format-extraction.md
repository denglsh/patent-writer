# 参考专利格式提取提示词

本文件用于阶段 A 选项 3：用户提供了参考专利（模仿对象），skill 从中提取格式，
生成一份"逐章节撰写提示词"（playbook），再由本 skill 自己按 SKILL.md 阶段 B 逐步执行。
产出格式必须比照内置 `writing-playbook-cn.md`（总纲 + 第0步 + 逐章节步骤 + 终检），
这样阶段 B 的执行逻辑无需改动。

## 输入

参考专利全文：用户提供的 .docx / .pdf / .md 路径或粘贴文本（.docx 用 documents:docx 技能读，.pdf 用 pdf 技能读）。
skill 自带参考专利位于本 skill 的 `assets/` 目录（2026D0071IN，风电叶片应变传感器布局方法及系统）——"用自带"路径一般直接用内置 playbook，无需重新提取。
若用户同时已给出自己的技术框架，先提取格式再进入第0步；两者顺序按用户提供的先后互换。

## 提取维度（对每个章节逐项分析）

按专利文档顺序逐章节分析：摘要 → 权利要求书 → 说明书（发明名称/技术领域/背景技术/发明内容/附图说明/具体实施方式）→（如有）附图清单。

1. **格式结构**：小节划分与顺序；段落数量与套路；权利要求条数与分层（独权/从权/镜像系统权利要求/电子设备/存储介质）；编号样式（半角/全角）；固定套话——逐字摘录原文；"方法+系统+电子设备+存储介质"四件套布局是否存在、如何体现。
2. **字数**：每章、每段、每条权利要求实测统计，给区间（如 450~500 字）；标出篇幅最重的章节与最重的段。
3. **撰写风格**：句式特征（动词开头、"、"衔接小句、分号串联长句）；"所述"使用纪律；人称与自称；参数与公式的表述方式（是否文字化为"其中，A为……"）；枚举句式（"包括A、B、C和D"）。
4. **重点倾向**：细节集中在哪个章节；哪些部分互为逐字镜像（权利要求↔发明内容↔实施例步骤段↔系统模块段）；背景技术不足与发明点/有益效果的对应条数。
5. **详略程度**：章节内部的展开模式与长度比（如实施例"步骤段 : 扩写段 ≈ 1:3"）；实例段的数值颗粒度（型号/尺寸/材料/偏差/工况/迭代次数/对比结论）。

## 产出（一份可直接执行的 playbook）

1. **总纲**：文件结构与总体布局 / 复用纪律 / 语言风格 / 详略规则 / 输出纪律，五节，比照内置 playbook 的总纲写法。
2. **第0步｜方案拆解**：从参考专利反推——发明名称命名格式；发明点清单的条数与写法；步骤化方案的步数与功能骨架（**忠实于参考专利**：它是 S1~S5+S6 就写 S1~S5+S6，是别的步数就按实际，不要硬套五步）；关键名词表要求。
3. **逐章节步骤块**：每章一块，含字数区间、模板句式（自原文摘录改写为占位模板）、禁止事项、本章自检清单。
4. **末步｜全文终检**：从参考专利特征反推的检查项（镜像比对、术语一致性、"所述"链条、编号格式、字数、数值自洽等）。

## 硬性要求

- 固定套话逐字摘录自参考专利，禁止改写；其余模板句用"【占位】"标注需替换处。
- 字数给实测区间，不给单值。
- 步数、权利要求条数、章节布局忠实于参考专利，不按内置 playbook 硬套。
- 实例段的数值颗粒度照参考专利定要求；具体数值留待撰写时替换为用户方案的数值。
- playbook 生成后：先展示总纲 + 步骤骨架请用户编号确认；确认后保存为
  `<工作目录>/playbook-<参考专利号或日期>.md`，后续阶段 B 改用该文件执行。
- 若用户想把新 playbook 设为以后的自带模板，提示其可另存到本 skill 的 references/ 目录（勿覆盖内置 writing-playbook-cn.md）。
